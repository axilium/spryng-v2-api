## API overview

This endpoint allows you to send single or bulk messages at a future date / time. This lets you schedule your communications in advance so they arrive when they'll be most effective. This can be configured to send messages as a one off at a future date/time or the schedule can be set to repeat on a regular basis i.e. monthly. All schedule times should be provided in UTC.

As with v2/messages, you use this endpoint to send to either a recipient list or previously created contacts/ groups to any available channel using either existing templates or text provided in the request body.

Before you start using this endpoint, please check you have your Account, API Key and Base URL set up and have familiarised yourself with our implementation prerequisites.

## URL & method

```
https://api.spryng.nl/v2/schedules/delayed
```

**Method: POST**

## Headers

These parameters are mandatory to be provided in the header of your request. If not provided, or incorrect, your request will fail.

| Header | Type | Description |
| --- | --- | --- |
| X-Api-Key | String | API Key value for authorization |
| Content-Type | String | application/json |
| AccountReference | String | Your Spryng account reference - e.g. SPNL0000000 |

**Example request header:**

```

-H 'Api-Key: YOUR_API_KEY'
-H 'AccountReference: SPNL0000000'

```

## Request body

You can use the cURL sample provided on the right hand side of this page to directly copy/paste into your chosen integration tool, using the below properties to modify your request as required for your business needs.

**Required, or conditional, request body parameters**

If a required parameter is not provided, or incorrect, the request will fail. If a parameter is conditional, it is only required for certain channels or is dependent on the desired format of the message.

| Property | Type | Required or Conditional | Description |
| --- | --- | --- | --- |
| scheduleInformation | JSON Object | Required | Contains all the information required to determine when the scheduled message start |
| scheduleInformation.sendTime | String | Required | The time the message should be sent provided in ICT format format YYYY-MM-DD:HH:MMZ e.g. 2025-03-05T11:47:25.723Z. The platform operates in UTC time zone exclusively. If you want to schedule a message to correspond to a different time zone |
| scheduleInformation.frequency | String | Conditional | The interval in which the message schedule should repeat e.g. Monthly. Required only if the message should be set to repeat. Accepted entries include Daily \| Weekly \| Monthly \| Annually \| Weekdays & Weekends. To schedule a single message request. Both "frequency" and "repeatTimes" must be omitted |
| scheduleInformation.repeatTimes | String | Conditional | The number of times the message schedule should repeat provided as a numeric value e.g. 2. This parameter is required when "frequency" is provided. If "frequency" is provided and "repeatTimes" is not specified the repeat times will be infinite. If "repeatTimes" is provided without "frequency" the request will error. To schedule a single message request both "frequency" and "repeatTimes" must be omitted |
| dispatch | JSON object | Required | Properties as below |
| dispatch.channel | String | Required | The channel to be used for the message provided as an Enum e.g. SMS |
| dispatch.from | String | Conditional | The originator to be used for the request. This can be alphanumeric or numeric. If numeric it must be a VMN or Shortcode that you have purchased. If alphanumeric then you may need to register the senderId in advance depending on the destination country regulations. You can set a default senderId in your Spryng portal account |
| dispatch.body | JSON object | Required | The content of the message being sent. It can contain 2 possible strings either: “text"or “templateId". If using “text” this should be provided as a String. Variables can be provided using square brackets. If using “templateId” this should be provided as a GUID. “templateId” must correspond to a previously created and accepted. Either “text” or “templateId” must be provided within the body |
| body.text | String | Conditional | Required if not using "templateId".Text in the message body should be provided as a String. Variables can be provided using square brackets such as “variablename1” and “example2”. Only one of “text” or “templateId” should be provided within a request. If you would like to include a shortened URL within your message body |
| body.templateId | String | Conditional | The value of the template you wish to use in your message |
| recipients.msisdn | String | Conditional | The phone number of recipient provided as a string in E.164 international format e.g. “447xxxxxxxx”. Use "recipients" if you wish to send to a number which is not registered as a contact. Can contain an array of recipient objects between 1 & 50000. Either "recipients" or "addressBook" must be provided |
| addressBook | JSON object | Conditional | Use "addressBook" if you wish to send to existing contacts. If using "addressBook" "addressBook.contacts" & "addressBook.contacts.id" will be required. A max of 50000 contacts can be included in a single request |
| addressBook.contacts | JSON array | Conditional | Required when using "addressBook". Can contain an array of contacts. Each contact must correspond to a contactId that belongs to the account which is sending the message. Using contactIds allow the data in each contact's custom fields to be used as variables in the message body. A max of 50000 contacts can be included in a single request |

**Optional request body parameters**

These parameters are not mandatory within the request body, they are designed to provide you further capability to customise or filter your requests.

| Paramter | Type | Description |
| --- | --- | --- |
| dispatch.characterSet | String | Allowed character sets are: Auto \| GSM \| Unicode. GSM uses a smaller characterSet which allows characters per message part to around 140. Unicode allows using of a large set of special characters and unicode emojis but reduces characters per message part to around 70. Auto means we will detect the characters provided and use GSM when only GSM characters are present |
| dispatch.messageType | String | Used to help your reporting on certain message types. Enum e.g. MarketingAndResearch \| NotificationsAndReminders \| AuthenticationAndSecurity \| PaymentsAndCollections \| InternalOperations \| CustomerSupport \| Conversational |
| dispatch.name | String | Optional friendly name for the request. Will be present message history export and can make some data analysis or grouping easier |
| metaData | JSON object | Can contain "key": "value" pairs. These are saved with the message and will be returned when exporting the message history. This can make some data analysis easier |

In order to shorten a URL within a message, embed [shorten: http://example/longURL.com] into the request "body.text" parameter. The platform will then automatically convert your long URL into a shortened URL.

To see an example of this request, see the request body examples section below. Please note, the shorten URL capability is not available during Trial. You will need to upgrade to a full account to use this feature.
