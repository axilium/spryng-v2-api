## API overview

This endpoint can be used to increase the authentication required for webhooks on an account. This increases security for webhooks used, meaning a consumer can verify they’re receiving a webhook from an expected source and the webhook producer can verify the customer.

There are 3 possible authentication methods available:

- Basic Authentication/ Username & Password
- OAuth Verification Token/ Bearer Token
- Custom Headers/ API Key

**A maximum of one authentication method can be set per account**.If the type of the authentication method is updated, this is automatically reflected on all existing subscriptions of that account.If more than one authentication method is specified, the request will fail with a 400 status code.

## OAuth Verification Token

Token (bearer) authentication is a standard method to authenticate webhooks. This is an OAuth verification protocol that allows users to verify their identity on a web application, receive an access token and verify each request to the web app with the access token. The authenticated request uses the authorization header to send the token using the format below:

```
authorization: Bearer {token}
```

Webhook consumers can use this strategy to authenticate webhook requests arriving at the webhook URL.
OAuth 2.0 requires an authentication token, which is issued by an authorization server, in order to connect to customer webhook endpoint. The authentication token is checked by the receiving endpoint when accepting the HTTP request.
To configure OAuth 2.0, customers need to provide the following information:

- OAuth2 Client ID and OAuth2 Client Secret that the platform will use to request the authentication token from your authorization server
- OAuth2 Token URL i.e. the URL of the authorization server from which the platform will request the token

Once this has been configured, you then need to define the authentication method during webhook subscription creation/editing. This can be done specifying the authentication method Id.
Once set up, the platform will request a token when we are attempting to send data to the webhook target. We also request a token when a webhook is initially created, or later modified/updated.

**OAuth required headers**

| Property | Type | Description |
| --- | --- | --- |
| clientIdValue | String | Client ID that the platform will use to request the authentication token from customer authorization server |
| clientSecretIdPropertyValue | String | Client Secret that the platform will use to request the authentication token from customer authorization server |
| clientSecurityValue | String | The secret value specified for authentication |
| clientSecretPropertyName | String | The name of the secret value |
| tokenUrl | String | Contains the URL the authorization server from which the platform will request the token |
| accessTokenPropertyName | String | The name given to the access token |

                  response.append(line.trim());
              }
            }
        }

          try (var errorReader = new java.io.BufferedReader(new java.io.InputStreamReader(connection.getErrorStream(), StandardCharsets.UTF_8))) {

            String line;

                errorResponse.append(line.trim());
            }

          } catch (Exception e) {
            System.err.println("Failed to read error response: " + e.getMessage());
          }
        }

        connection.disconnect();
    }
