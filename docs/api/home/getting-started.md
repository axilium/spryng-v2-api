## Authentication

Spryng APIs use API Key access to authenticate requests. In order to use our APIs, you will need an Spryng account. To start a free trial, either click the **"Try for free"** in the top right of this website or contact the Spryng team. Once you have access to your account, you will be able to create, use and manage your API Key tokens and other settings via the [Spryng Portal.](https://app.Spryng.co.uk)

**To create/access an API key:**

- Navigate to the [Spryng portal](https://app.Spryng.co.uk) in your browser
- Log in using the credentials you created when you set up your account or sign up for a free trial account by clicking "Try for free"
- Complete Multi-Factor authentication
- Ensure you have been allocated Admin and Developer user status of the account - you’ll need this to access settings and the Developer Tools area
- In the Spryng Portal navigate to the Developer Tools area via the side navigation. Ensure you have been allocated Developer access
- Create new API key if required* - existing API Keys will be should be shown in a list
- Retrieve your API Key and copy it into the request

*For more information on how to create an API key, there is a [video guide here](https://www.youtube.com/watch?v=4wwL8M60FpE)

While generating an API Key, an expiration date should be added for security best practice. If no expiration date is added, the API key will permanently exist until deleted or an expiration date is added.

API Keys can be independently revoked, so you have complete control of the lifecycle of your API credentials. For example, you might issue separate API Keys to different developers or different subsystems within your application. If a key is compromised or no longer used, you can delete it to prevent unauthorized access.

*Reminder: API credentials, including API key and account reference, need to be kept secure at all times. This means not sharing in any public areas or with anyone else, including in client code, in public forums or with other users. These credentials give authorization to use our products and therefore need to be protected.

## Base URL

The API is served over HTTPS to ensure data privacy, unencrypted HTTP is not supported.

All API resources are using the following base url:

```
https://api.spryng.nl
```

## Prerequisites

**HTTPS** 
Our APIs are built on a RESTful endpoint structure and served using HTTPS to ensure data privacy; unencrypted HTTP is not supported.
If you use a popular web browser such as Chrome, Safari, Internet Explorer or Firefox and you update it when prompted, your connection should be secure and you should already be connecting via a secure TLS connection such as HTTPS.

**Programming Languages supported**
We support multiple programming languages, including C#, PHP, Python, Java and Node.js and use JSON-encoded responses with conventional HTTPS response codes.

**Multi-factor authentication**
Multi-factor authentication, sometimes referred to as 2 Factor Authentication (2FA), is an extra layer of security that, when triggered, will ask the user to provide additional information to verify who they are before they’re able to login to their account. You’ll need to use multi-factor authentication when you set up your account, and every time you log into the Spryng portal after this.
If you have an account in multiple territories (countries), you will need to set up MFA for each territory.

For more information on setting up MFA, please follow this [guide](https://support.Spryng.co.uk/article/sms/multi-factor-authentication)

## IP addresses

Our API platform is offered from a globally distributed infrastructure, so you won't be able to whitelist the IP addresses of our platform. Keep in mind that requests for delivery reports and inbound messages originate from various IP addresses. If you have a firewall in place, we recommend reviewing the inbound rules for your DNS.

## Rate limiting

Rate limiting restricts the number of API calls which can be made within a defined time period. Rate limiting acts as a basic security measure against malicious attacks, such as Denial-of-Service (DoS) attacks as well as ensuring an even flow of messages through the platform enabling the best performance possible.

If you hit our rate limit, you will receive a **429 error response**

We currently have a default rate limit for all our public API endpoints. If the rate limit is reached, you will need to wait 5 seconds before doing another request. As the Spryng platform is cloud native, it can be scaled to handle higher throughput figures as required.

If you would like to know more details or request a change to your rate limit configuration, please contact our Sales team.

## Versioning

The Spryng API includes the version being used in the URL

```
POST https://api.Spryng.com/v2/messages
```

When backwards-incompatible changes are made to the API, a new version is released.

Breaking changes include:

- A change in the format of the response data for one or more calls
- A change in the request or response type - i.e. changing an Integer to a float
- Removing any part of the API

All breaking changes should result in a change of major version number.
